# Reliability, Trace, and Archive Operations

This document explains the timeout, `Trace-Id`, and request/response archive behavior added for high-volume relay operation.

## Customer Trace-Id

Clients may send one optional header:

```http
Trace-Id: Abc123
```

Rules:

- only `Trace-Id` is accepted
- missing header is allowed and becomes an empty `trace_id`
- present but empty value is rejected
- multiple `Trace-Id` values are rejected
- only ASCII letters and digits are allowed
- maximum length is 64 characters
- whitespace at the start, end, or inside the value is rejected
- case is preserved

The server-generated request ID and customer trace ID are separate:

- server request ID: `request_id`, generated by the gateway
- customer trace ID: `trace_id`, supplied by the caller

`trace_id` appears in:

- Gin context
- request context
- runtime logs next to `request_id`
- consume and error log `logs.other.trace_id`
- archive manifest and object metadata

Archive object paths are keyed by `request_id`; `trace_id` is metadata, not the path key.

## Timeout Controls

Channel timeout settings live in `channel.setting` JSON:

- `non_stream_timeout_seconds`
- `stream_first_byte_timeout_seconds`

AWS Bedrock-specific retained controls are:

- global `AWS_INVOKE_TIMEOUT_SECONDS`
- global `AWS_SDK_MAX_ATTEMPTS`
- per-channel `aws_invoke_timeout_seconds`
- per-channel `aws_sdk_max_attempts`

AWS HTTP client timeout configuration and `retry_mode` are not part of the retained configuration surface.

Timeout metadata is written into `logs.other` when available:

- `timeout_type`
- `timeout_source`
- `timeout_seconds`
- `timeout_provider`
- `timeout_stage`
- `retry_index`
- `is_stream`

Timeout failures remain compatible with retry when the existing retry rules allow it.

## Request/Response Archive

Archival is disabled by default.

Enable it with:

```bash
ARCHIVE_ENABLED=true
```

The first version covers:

- main HTTP relay routes
- Gemini relay routes
- task/video routes
- video content proxy
- Suno task routes

The first version does not cover:

- realtime WebSocket
- Midjourney routes
- channel-test routes

Each archived request has three logical objects:

- `manifest.json.gz`
- `request.data.gz`
- `response.data.gz`

Local storage layout:

```text
<ARCHIVE_LOCAL_DIR>/
  spool/
  objects/
    <request_id>/
      manifest.json.gz
      request.data.gz
      response.data.gz
```

Azure Blob layout:

```text
<request_id>/manifest.json.gz
<request_id>/request.data.gz
<request_id>/response.data.gz
```

The manifest includes:

- `request_id`
- `trace_id`
- `trace_id_present`
- request method and path
- HTTP status
- stream flag
- storage mode
- request object status, bytes, content type, hash
- response object status, bytes, content type, hash
- retry attempt summaries

## Archive Configuration

| Variable | Meaning | Default |
| --- | --- | --- |
| `ARCHIVE_ENABLED` | Enables archive middleware and workers | `false` |
| `ARCHIVE_BACKEND` | `local` or `azure_blob` | `local` |
| `ARCHIVE_LOCAL_DIR` | Local archive root | `./data/archive` |
| `ARCHIVE_SPOOL_DIR` | Spool directory; defaults to `<ARCHIVE_LOCAL_DIR>/spool` | empty |
| `ARCHIVE_QUEUE_SIZE` | Bounded archive queue size | `50000` |
| `ARCHIVE_WORKER_COUNT` | Archive worker count | `32` |
| `ARCHIVE_MAX_REQUEST_MB` | Max request object size before skip | `128` |
| `ARCHIVE_MAX_RESPONSE_MB` | Max response object size before skip | `128` |
| `ARCHIVE_SPOOL_TTL_HOURS` | Retention for failed spool files | `24` |
| `ARCHIVE_AZURE_ACCOUNT_URL` | Azure Blob service URL or SAS URL | empty |
| `ARCHIVE_AZURE_CONTAINER` | Azure Blob container name | empty |
| `ARCHIVE_AZURE_ACCOUNT_NAME` | Azure account name for shared key auth | empty |
| `ARCHIVE_AZURE_ACCOUNT_KEY` | Azure account key for shared key auth | empty |

For local storage, set:

```bash
ARCHIVE_ENABLED=true
ARCHIVE_BACKEND=local
ARCHIVE_LOCAL_DIR=/data/archive
```

For Azure Blob with shared key auth, set:

```bash
ARCHIVE_ENABLED=true
ARCHIVE_BACKEND=azure_blob
ARCHIVE_AZURE_ACCOUNT_URL=https://<account>.blob.core.windows.net/
ARCHIVE_AZURE_CONTAINER=<container>
ARCHIVE_AZURE_ACCOUNT_NAME=<account>
ARCHIVE_AZURE_ACCOUNT_KEY=<key>
```

For Azure Blob with SAS in the URL, set `ARCHIVE_AZURE_ACCOUNT_URL` to the SAS URL and omit account name/key.

## Failure Behavior

Archive failures do not fail successful customer responses.

Failure and skip statuses are recorded in `logs.other.archive` and runtime logs:

- queue full: archive is skipped with reason `queue_full`
- request over size limit: request object is skipped with reason `request_size_limit`
- response over size limit: response object is skipped with reason `response_size_limit`
- spool write failure: archive object records spool failure
- backend write failure: archive status becomes failed

Oversized objects are skipped, not truncated.

Queue items contain metadata and spool file paths only; they do not contain raw request or response bytes.

## Verification

Useful local verification commands:

```bash
GOROOT=/Users/zf/.gvm/gos/go1.25.1 go test ./service/archive ./middleware ./router ./model
GOROOT=/Users/zf/.gvm/gos/go1.25.1 go test ./controller -run '^$'
```

When running locally with archive enabled:

1. Send a relay request with and without `Trace-Id`.
2. Confirm the response still returns normally.
3. Check `logs.other.trace_id`.
4. Check `logs.other.archive`.
5. Check `<ARCHIVE_LOCAL_DIR>/objects/<request_id>/`.
6. Decompress `manifest.json.gz` and confirm `trace_id`, object status, and byte counts.
